# HANAMORPH — Artifact Generation Engine Engineering Guide

## 1. OVERVIEW & GENERATION PREREQUISITES
The Artifact Generation Engine produces ready-to-deploy, standard-compliant schema definitions, SQL statements, and technical mappings for target platforms.

### 1.1 Mandatory Human Approval Gate
In accordance with enterprise governance:
- Code generation **cannot be triggered on draft plans**.
- The parent architecture plan must possess `status = 'APPROVED'` in `architecture_plans`.
- If an unapproved plan is submitted to `/api/generation/generate`, the engine rejects the request with HTTP 403 / `PLAN_NOT_APPROVED_ERROR`.

## 2. GENERATED ARTIFACT TYPES

For each in-scope canonical object, the engine produces three distinct artifacts:

### 2.1 Core Schema Notation (`.csn.json`)
The SAP standard format for defining data models in SAP Datasphere and SAP Cloud Application Programming Model (CAP):
```json
{
  "$schema": "https://cap.cloud.sap/schemas/csn.json",
  "definitions": {
    "MIGRATION_SPACE.ADSO_SALES_ACT": {
      "kind": "entity",
      "@EndUserText.label": "Actual Sales Transactions",
      "elements": {
        "SALES_DOC": {
          "type": "cds.String",
          "length": 10,
          "key": true,
          "notNull": true
        },
        "NET_AMOUNT": {
          "type": "cds.Decimal",
          "precision": 15,
          "scale": 2
        }
      }
    }
  }
}
```

### 2.2 SAP HANA SQL DDL (`.sql`)
High-performance DDL statements compatible with SAP HANA Cloud:
```sql
-- Generated by HANAMORPH for object ADSO_SALES_ACT
-- Plan ID: PLAN_20261121_001
-- Route: native_datasphere

CREATE COLUMN TABLE "MIGRATION_SPACE"."ADSO_SALES_ACT" (
    "SALES_DOC" NVARCHAR(10) NOT NULL,
    "NET_AMOUNT" DECIMAL(15, 2),
    PRIMARY KEY ("SALES_DOC")
);
```

### 2.3 Field Mapping Specification (`_mapping.md`)
Human-readable markdown documentation detailing transformation lineages, field derivations, and source-to-target correspondences.

## 3. LOCAL FILE SYSTEM ORGANIZATION

All generated files are written strictly to the local workspace:
```
BW_Migration_Studio/bw-studio/output/
└── <project_id>/
    └── <plan_id>/
        ├── manifest.json
        ├── ADSO_SALES_ACT.csn.json
        ├── ADSO_SALES_ACT.sql
        ├── ADSO_SALES_ACT_mapping.md
        ├── CP_SALES_GL.csn.json
        ├── CP_SALES_GL.sql
        └── CP_SALES_GL_mapping.md
```

Each artifact is registered in the SQLite `generated_artifacts` table with its exact file path, byte size, and SHA-256 checksum.
